# 頁面規格總覽

這個資料夾把 Phase 1 已經定案的業務規則（[功能需求.md](../功能需求.md) 的 10 個 User Story、[規格書.md](../規格書.md) 的 FR-1～FR-12）**改成「依畫面分類」重新整理一次**，回答的問題是：正式開發到底要開幾個畫面／彈出視窗，每個畫面各自要做什麼。

**這份文件不新增、也不覆蓋任何業務規則**——如果這裡的描述跟 [功能需求.md](../功能需求.md)、[規格書.md](../規格書.md) 對不上，一律以那兩份文件為準，這裡只是換一個角度整理同樣的內容，方便切分前端開發工作。

**畫面清單是怎麼列出來的**：現有的純前端 prototype（同一個 repo，`src/`）已經把大部分畫面實際做出來並收集過初步 UX 回饋，所以下面的畫面清單以 prototype 目前的畫面結構為參考基準逐一對照 User Story 整理而成。但比照 [規格書.md](../規格書.md) 一貫的立場：**畫面的視覺設計、版面配置可以完全重新來過**，這裡固定下來的只有「有哪些畫面、每個畫面要滿足哪些已定案的功能」，不是要求照抄 prototype 的視覺或元件切法。

**只寫一套，不分桌面／手機**：prototype 目前有桌面（`src/components/*`）、手機（`src/mobile/*`）兩套獨立的 UI 樹（細節見專案 [CLAUDE.md](../../../CLAUDE.md)），但兩者除了「建立活動」是單頁表單 vs. 三步驟精靈之外，其餘畫面（投票、彙整、已定案、已取消、留言板、各彈出視窗）欄位與行為完全一致。下面的頁面規格只描述**一套響應式畫面**該有的功能，不主張要維持 prototype 現有的兩棵獨立 UI 樹這種實作方式。

## 到底要開多少東西

| 層級 | 數量 | 說明 |
|---|---|---|
| **路由／進入點** | 2 個 | 主站首頁（無事件 hash）、活動頁（`#event=<id>`） |
| **畫面／狀態**（同一路由依狀態切換出的不同內容） | 9 個 | 見下表；主站首頁因 2026-09-01 追加的 FR-12 登入閘門，從 1 個畫面拆成 3 個 |
| **彈出視窗（Modal）** | 5 個 | 疊加在路由之上，不改變網址 |
| **已定案畫面上的追加浮層** | 1 個 | AI 選餐廳（2026-09-02 追加，見 [05-AI選餐廳.md](./05-AI選餐廳.md)） |
| **全域元件** | 1 個 | Toast 通知，疊加在所有畫面之上 |
