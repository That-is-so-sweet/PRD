# 頁面 01：建立活動頁

## 基本資訊

- **路由**：預設畫面——`window.location.hash` 沒有指向任何活動時顯示
- **對應 User Story**：[001：建立活動並取得分享連結](../功能需求.md#user-story-001建立活動並取得分享連結)
- **對應 FR**：FR-1（建立活動）、FR-2（分享連結）
- **對應現有 prototype 元件**（僅供參考，畫面可重新設計）：桌面版 `CreateEvent.tsx`（單頁表單＋即時預覽）、手機版 `CreateWizard.tsx`（拆成 3 步驟：基本資訊／候選日期與時段／預覽送出）；兩者欄位與驗證規則完全相同，只有「一頁到底」vs.「分步驟」的呈現方式不同

## 這個頁面要做什麼

主揪在這裡填完所有建立活動所需的資訊，送出後立即拿到一個可分享連結。不論最終拆成幾個步驟呈現，都必須涵蓋以下三組欄位與行為。

### 1. 基本資訊欄位

| 欄位 | 必填／選填 | 規則 |
|---|---|---|
| 活動名稱 | 必填 | 去除頭尾空白後 1–30 字 |
| 主揪姓名 | 必填 | 中英文加權字元計算，總單位數上限 40（見 [規格書.md 4.2 節](../規格書.md#42-各功能詳細規格)「中英文長度規則」） |
| 主揪 Email | 選填 | 需符合 Email 格式；一旦填寫，日後主揪身分驗證需與姓名一併核對（Scenario 9） |
| 候選時段模式 | 必填（`date_only` / `time_slots` 二擇一） | 建立後不可變更，不可混用 |
| 回覆截止時間 | 必填 | 必須晚於送出當下的時間；前端用日期選擇器擋過去時間，**後端仍須重新驗證**（Scenario 10） |
| 地點 | 選填 | 文字或網址，≤200 字（URL 格式需額外驗證） |
| 活動說明 | 選填 | ≤50 字 |

任何一項驗證不通過都要阻擋送出並提示明確錯誤（Scenario 2、3、6、8、9、10）；前端擋過的規則，後端要重新驗證一次，不能只信任前端。

### 2. 候選時段選擇

- 候選時段 1–20 筆（Scenario 4：至少 1 筆；Scenario 5：超過 20 筆要阻擋，前端達到上限應直接鎖住「新增」操作）
- `date_only` 模式：只選日期，不細分時段
- `time_slots` 模式：每個日期可加一或多個時間點＋自訂標籤（例如「午餐」「討論」）
- 多天活動需要有「一次套用到多個日期」的操作方式，降低逐天輸入的成本（現有 prototype 提供「加入全部日期」與「常用時段」兩種輔助操作，可作為參考，不強制照抄）

### 3. 草稿保存與送出

- 填寫過程中內容需自動保存到瀏覽器本機（Scenario 11）——這是前端 UX 需求，草稿內容不需要同步到伺服器（見 [規格書.md FR-1](../規格書.md#41-功能需求總表)）
- 使用者中途離開、重新整理、切換分頁再回來，先前填寫的內容都要還在
- 主動選擇「發起新活動」開始一個全新的建立流程時，會覆蓋掉前一次未完成的草稿，同時只保留一份（Scenario 12）
- 送出成功後：
  1. 產生全域唯一活動 ID 與可分享連結
  2. 若有填主揪 Email，寄送含分享連結的通知信（Scenario 7）
  3. 清除本機草稿
  4. 直接帶使用者進入 [活動頁](./02-活動頁.md)（彙整結果畫面）
  5. 同時自動開啟 [分享 Modal](./04-彈出視窗與全域元件.md#分享-modal)，讓主揪立刻複製連結

## 不屬於這個頁面的事

- 候選時段一旦送出就不能在建立活動頁修改——要調整候選時段只能取消活動後重新建立一個
- 活動名稱／地點／說明等基本資訊，送出後若要改，是 [活動頁「編輯活動資訊」Modal](./04-彈出視窗與全域元件.md#編輯活動資訊-modal) 的功能，不在這個頁面
