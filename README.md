# 揪甘心 — 產品規格文件索引

## 目錄

### 產品規劃

1. **[產品概觀](./產品規劃/產品概觀.md)** — 一句話說清楚、我們要解決的問題、我們在為誰做、為什麼是現在、我們打算怎麼做、怎麼知道有沒有成功
2. **[開放問題與規劃](./產品規劃/開放問題與規劃.md)** — 還沒決定的事、怎麼排優先順序、之後打算怎麼做、這份文件哪裡強哪裡弱

### 開發規格

3. **[功能需求](./開發規格/功能需求.md)** — 完整 BDD 格式的 User Stories、我們不做的事、依賴與風險（給工程團隊直接對照開發與測試）
4. **[規格書](./開發規格/規格書.md)** — 功能需求細表、資料庫 schema、API 設計、安全性設計、非功能需求、開放問題
5. **[流程圖](./開發規格/流程圖.md)** — 主流程圖與活動狀態轉換圖
6. **[頁面規格](./開發規格/頁面規格/README.md)** — 把功能需求／規格書改成依畫面分類：要開多少頁面／彈出視窗、各自的功能是什麼

## 資料夾結構

```
PRD/
├── README.md              — 本檔案，總索引
├── 產品規劃/                — 產品層文件，口語化，方便不同背景的人都能看懂
│   ├── 產品概觀.md          — 一句話說明、問題、使用者、為什麼是現在、怎麼算成功
│   └── 開放問題與規劃.md     — 還沒拍板的問題、優先順序、後續 Phase 規劃、文件強弱點
└── 開發規格/                — 工程團隊直接對照開發與測試用，保留完整技術細節
    ├── 功能需求.md          — 完整 BDD／Gherkin 格式的 User Stories、不做的事、依賴與風險
    ├── 規格書.md            — 技術規格：功能需求細表、資料庫 schema、API 設計、安全性、開放問題
    ├── 流程圖.md            — Mermaid 主流程圖與活動狀態轉換圖
    └── 頁面規格/             — 同一批業務規則改以「畫面」分類，回答要開多少頁面／彈出視窗
        ├── README.md            — 總覽：頁面／彈出視窗數量、User Story 對照表
        ├── 01-建立活動頁.md
        ├── 02-活動頁.md          — 投票／彙整／已定案／已取消四種狀態＋留言板
        ├── 03-系統狀態畫面.md     — 連結已失效、讀取錯誤
        ├── 04-彈出視窗與全域元件.md
        └── 05-AI選餐廳.md        — 已定案畫面上的追加浮層，2026-09-02 會議追加
```

**分類原則**：「產品規劃」放策略與敘事類內容（問題定義、使用者輪廓、路線圖），寫給不限工程背景的人看；「開發規格」放需要照著實作與測試的內容（驗證規則、資料模型、API、Gherkin Scenario），是給工程團隊的開發依據。

**四份主要文件的關係**：[產品概觀.md](./產品規劃/產品概觀.md) 是產品層的敘事（問題、使用者、成功指標）；[規格書.md](./開發規格/規格書.md) 是對應的開發規格（技術架構、資料庫 schema、API 設計）；[流程圖.md](./開發規格/流程圖.md) 用 Mermaid 圖呈現完整系統流程與活動狀態轉換；[功能需求.md](./開發規格/功能需求.md) 是完整 BDD 格式的 User Stories，工程團隊開發與測試時應直接對照這份文件與規格書.md；[頁面規格/](./開發規格/頁面規格/README.md) 不新增規則，只是把功能需求.md／規格書.md 的內容改成依「畫面」分類，方便切分前端開發工作。以上文件的 Phase 1 範圍應保持一致，若頁面規格與功能需求.md／規格書.md 有出入，以後兩者為準。
